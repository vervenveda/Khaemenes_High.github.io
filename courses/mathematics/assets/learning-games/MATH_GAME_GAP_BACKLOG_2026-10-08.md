## Release criteria for every new game
- Verify mathematical correctness with edge cases and independent expected answers.
- No repeating the same question set after a reset or failed attempt; stable progress and fair fresh-question generation.
- Do not erase prior mastery/progress or force an entire restart because of one incorrect response.
- Keyboard-accessible controls, clear instructions, reduced-motion consideration, no inaccessible drag-only tasks.
- Explicit lesson-alignment metadata and appropriate modes; no inflated reuse where concepts differ.
- Shared canonical HTML/JS/CSS, lightweight and offline-capable where feasible.
- Check every actual launch path and student-facing lesson connection; registry-only status is insufficient.
- 80% mastery policy must remain consistent with course engine; games should not silently overwrite grades.

## Audit limitations
This is a concept-level backlog derived from the canonical game registry, not an exhaustive lesson-by-lesson functional audit. Before building each P0 game, compare with existing lesson-native interactions and projects to avoid duplication. No game files or existing connections were modified in this report.
